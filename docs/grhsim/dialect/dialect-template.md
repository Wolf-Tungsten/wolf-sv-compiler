## 1. 定位

- 目标后端与代码生成路径（C++ / LLVM IR / …）；
- 与 generic 的关系：哪些 generic op 直接支持，哪些必须经方言下降重写；
- 不适用的场景。

## 2. 类型系统

本后端引入的类型清单。每个类型逐项给出：

- **语法与参数**：如 `cpu.bv64`；
- **精化关系**：实现哪个 generic 类型（GRHSIM IR 3.1 节）；
- **编码与布局规则**：位如何放入机器字、数组如何摊开、合并/拆分规则；
- **合法性**：保语义论证要点（对设计实际值域编码/解码无损）。

末尾必须定义方言混合处的类型衔接规则（GRHSIM IR 3.3 节）：generic 类型的
值能否被本后端 op 直接消费、反之如何、是否需要显式转换 op。

## 3. 操作清单

逐 op 定义，每个 op 一节：

```text
### <名称>.<op 名>

- **operands**：oper[0]（名字）：含义（类型）；…
- **results**：res[0]：含义（类型）；…
- **attrs**：key (类型)：含义；…
- **语义**：≤3 行的精确描述 + 必要时真值表/伪代码；
- **来源**：由哪个 generic op 经什么规则下降而来（或标注"后端独有，无
  generic 对应"）；
- **示例**：一段 GRHSIM IR 文本片段（before/after 各一段更佳）。
```

约束（GRHSIM 仿真模型 4.1 节）：op 必须确定、只能经 `H` 访问宿主；边缘触
发类 op 的效果同轮施加。

## 4. 存储特化

- StateDecl `backendType` 的取值集合与各自的布局规则；
- `S_in`、`S_out` 的对外 ABI（调用方如何驱动输入、采样输出）；
- `S_edge` 条目的表示（随被跟踪信号，或本后端的特化约定）。
